# Edge node firmware

MicroPython firmware for the edge node of the near-miss fall detection system: a
TinyS3 (ESP32-S3) reads a WitMotion WT9011DCL-BT50 IMU over BLE, classifies every
window of data on the device and publishes one MQTT message for each detected
near-miss event on the local (edge-level) broker, from which the fog node forwards
it to the cloud. Raw IMU data never leave the device.

## How it works

1. **Acquisition** (`coroutines/data_processor.py`). Samples of the 9 channels used
   by the system (acceleration, angular velocity, Euler angles) are decoded and
   time-stamped with the board clock. `ACQUISITION_MODE` selects how they are read:
   - `"3.5Hz"`: request/response loop of the dataset recordings. Each iteration
     lasts at least `SAMPLE_PERIOD_MS` (284 ms, the mean sampling interval of the
     dataset), so the model receives the sampling rate it was trained on. The
     magnetometer request/reply is kept in the loop for timing only; its values are
     not used.
   - `"100Hz"`: the sensor streams its packets at 100 Hz. No 100 Hz model is
     deployed (see *Switching to 100 Hz*).
2. **Preprocessing** (`coroutines/preprocessor.py`). Vector magnitudes (`AccMag`,
   `GyroMag`, `AngMag`) are computed and every sample is stored in a ring buffer
   (`lib/sample_buffer.py`).
3. **Inference** (`coroutines/machine_learning_inference.py`). Every `STEP_MS`
   (1 s) the samples of the last `WINDOW_MS` (2 s) are taken from the buffer.
   Windows that cannot be processed reliably (fewer than `MIN_WINDOW_SAMPLES`
   samples, or a non-finite feature) are discarded, as in the training pipeline.
   The features are computed with the definitions of the training pipeline
   (`lib/window_features.py`), standardised with the training scaler and classified
   by the model with its default decision rule (score > 0.5).
4. **Events**. Consecutive near-miss windows form one event, from the start of the
   first window to the end of the last one: the rule used in the event-level
   evaluation. When the event ends (first window classified as normal activity or
   discarded) one MQTT message is queued:

   ```json
   {"eventType": "near_miss", "timestamp": 847550617, "sensorId": "workers_1",
    "eventStart": 847550612369, "eventEnd": 847550616369,
    "durationMs": 4000, "windows": 3}
   ```

   `timestamp` is the detection time in seconds, `eventStart` and `eventEnd` are in
   milliseconds. By default times use the device epoch (2000-01-01 UTC on the ESP32);
   add 946,684,800 s for Unix time, or set `UNIX_EPOCH` to `true` (3 bytes more per
   message).
5. **Publication** (`coroutines/mqtt.py`). The outgoing queue holds up to ten
   messages. Detection continues while the network is down; queued messages are
   sent when the connection is restored, and a message leaves the queue only once
   it has been published. Messages use QoS 0: a message written on a connection
   that has silently died is lost.

## Deployed model

| | |
| --- | --- |
| Model | XGBoost, final model of the nested cross-validation (20 subjects) |
| Inputs | 9 channels (no magnetometer), 189 candidate features |
| Feature selection | θ = 30, 53 features |
| Trees / nodes | 300 / 23,150 |
| `lib/model_device.bin` | 325,300 bytes, SHA-256 `02e75cd34f5998ab92718be094543645b192478841c32b601f479784d55e3970` |
| Scaler | StandardScaler fitted on the 20 subjects, applied in `lib/model_device.py` |

The three model files in `lib/` are exported from the trained model by the training
pipeline. To use another model, replace `model_device.py`, `model_device.bin` and
`model_input_array.py`.

## Files on the device

Copy the content of this folder to the root of the TinyS3 (in Thonny: *View > Files*,
select the files on the computer side, right click > *Upload to /*). Do not copy
`__pycache__` folders or `README.md`.

```text
/
├── boot.py               10 s pause at start-up (time to stop the firmware from Thonny)
├── main.py               start-up: reads the configuration and starts all tasks
├── config.json           Wi-Fi, MQTT, IMU address, acquisition and window settings
├── battery_test.py       MODE = None for normal operation, or a measurement mode
├── tinys3.py             TinyS3 helper library (LED, battery voltage, USB detection)
├── coroutines/           acquisition, preprocessing, inference, MQTT, BLE scan, recording
├── lib/
│   ├── model_device.py        ┐ model files generated by the training pipeline
│   ├── model_device.bin       │
│   ├── model_input_array.py   ┘
│   ├── sample_buffer.py, window_features.py, wifi_manager.py, clock_sync.py, console.py
│   └── aioble/, primitives/, peripherals/
```

The firmware needs MicroPython for ESP32-S3 with `umqtt.simple`; `aioble` is
included in `lib/`. If `umqtt.simple` is not part of the MicroPython build, install
it from the computer with `mpremote mip install umqtt.simple`, or on the board,
once connected to Wi-Fi, with `import mip; mip.install("umqtt.simple")`.

## Configuration (`config.json`)

| key | meaning |
| --- | --- |
| `wifi_ssid`, `wifi_pass` | Wi-Fi network |
| `IMU_MAC_ADDRESS`, `IMU_SERVICE`, `IMU_CHAR_READ`, `IMU_CHAR_WRITE` | BLE address and UUIDs of the IMU |
| `ACQUISITION_MODE` | `"3.5Hz"` or `"100Hz"` |
| `SAMPLING_RATE_HZ` | expected samples per second (sizes the buffer): 3.5 or 100 |
| `SAMPLE_PERIOD_MS` | 3.5 Hz mode: minimum duration of one acquisition iteration (284 = dataset rate; 0 = no pacing) |
| `WINDOW_MS`, `STEP_MS` | window length and step (2000 and 1000: must match the model) |
| `MIN_WINDOW_SAMPLES` | windows with fewer samples are discarded (minimum 2) |
| `SENSOR_PERIOD_MS`, `SENSOR_CLOCK_RELAX_MS` | 100 Hz mode: sample clock of the sensor |
| `register_data_mode` | `true` = only record samples to `imu_data_<n>.json` on the board |
| `DEBUG_WINDOWS` | `true` = print decision, score and movement of every window (normal operation only) |
| `mqtt_broker`, `mqtt_port`, `mqtt_client_id`, `mqtt_topic`, `mqtt_user`, `mqtt_password` | edge-level broker and topic; `mqtt_client_id` is the `sensorId` |
| `ntp_host` | NTP server used to set the clock (a local server if the site has no Internet access) |
| `UNIX_EPOCH` | `false` = device epoch (2000, default); `true` = Unix times |

## First installation

1. In Thonny select the interpreter *MicroPython (ESP32)* and the port of the TinyS3.
2. Fill in `config.json`: replace the `YOUR_...` placeholders (Wi-Fi, broker address,
   IMU MAC address).
3. Upload the files as shown above.

## Normal use

- Power the board. LED: blue = searching for the IMU, three purple blinks = IMU found,
  green = connected and running, orange = connected in recording mode
  (`register_data_mode`), red = connection lost (the board reconnects by itself).
  No alarm is raised on the device: events are forwarded to the upper layers.
- Every second the last 2 s of data are classified. One MQTT message is published
  on `mqtt_topic` at the end of each near-miss event. To watch the messages:
  `mosquitto_sub -h <broker> -t '#' -v`.
- To work on the board from Thonny press *Stop*: the firmware stops and the REPL is
  available.
- The clock is set with NTP once, when the Wi-Fi connects.
- Console messages are printed only while USB is connected (`lib/console.py`):
  without a USB host, writing to the console can stall the firmware.
- The network may go down: MQTT socket operations have a 3 s timeout, reconnection
  attempts are spaced out (5 s doubling up to 60 s), the Wi-Fi connection is
  requested again every 30 s, and messages that do not fit in the outgoing queue are
  dropped instead of stopping the inference.

## Measurement modes

`battery_test.py` contains the modes used to measure the power consumption of the
system: each mode switches parts of the firmware on or off (acquisition only,
acquisition + inference, full system with MQTT) and writes a log file on the board
until the battery is exhausted. The modes and the test procedure are described in the
comments at the top of the file. For normal operation keep `MODE = None`.

## Switching to 100 Hz

Set `"ACQUISITION_MODE": "100Hz"` and `"SAMPLING_RATE_HZ": 100` (check
`SENSOR_PERIOD_MS`) and copy the three files of a 100 Hz model into `lib/`. Nothing
else changes.
